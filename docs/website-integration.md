# ربط Study Birds مع CRM

## الإصدار 15 — تعميم التحميل السريع على صفحات CRM

- طبقة API المشتركة تخدم قراءة `/api/settings` من إعدادات المؤسسة وآخر لقطة للدليل، ثم تحدث دليل الموقع في الخلفية. يستفيد القبول والاستقبال والمهام والتذكيرات والصندوق الموحد والإعدادات، بدل اقتصار الفصل على الاستشارات. مشاركة GET المتزامن وقراءة صفحات المصدر بالتوازي من الإصدار 14 تعمل لكل الصفحات التي تستخدم الطبقة المشتركة.
- الاستشارات والقبول والاستقبال تستقبل تحديثات الدليل لإكمال خيارات النماذج. الإعدادات تحدث روابط اختيارات الدليل دون إعادة تعيين حقول النموذج التي قد يعدلها المستخدم. فتح الإعدادات يقرأ لقطة الدليل المسجلة، وإدارة محتوى ودليل الموقع في الأقسام المخصصة تظل تستخدم نقاط المصدر الأصلية.
- النتائج الخلفية لا تطبق بعد إرسال كتابة جديدة أو تبديل الحساب. لا توجد ذاكرة استجابات دائمة في المتصفح، وتظل إجراءات الحفظ والإضافة والحذف تمر بالخادم كما هي.
- في الأقسام الموحدة، تحميل البيانات المحلية المساعدة بعد مزامنة المصدر يتم بالتوازي. وعلاقات الطالب (الطلبات والفواتير المسموحة) تقرأ بالتوازي مع الطالب بدل البدء بعدها. لا تزال مزامنة السجلات الأصلية تتم قبل إعادة قراءة القسم المحلي لضمان تحديثه.

التحقق: 76 اختبار ربط وبناء CRM، وفحص متصفح للمهام والتذكيرات والاستقبال والقبول والصندوق والإعدادات مع تعليق تحديث دليل الموقع عمدًا؛ ظهرت الصفحات قبل اكتماله دون أخطاء JavaScript، ثم وصل التحديث الخلفي. هذه نتائج محلية بواجهات API وهمية، وليست قياسًا لزمن Render أو Mongo في الإنتاج. التعديلات في خادم وواجهة CRM فقط، `websiteIntegration: 15`؛ الموقع يبقى الإصدار 13. لم يُغير تخزين قاعدة CRM العامة أو طابور الكتابة، ولم يدّع الاختبار إزالة كل تأخير يمكن أن تسببه الاستضافة أو حجم البيانات.



## الإصدار 14 — تقليل انتظار جلب البيانات

- الاستشارات: تحميل العملاء وإعدادات المؤسسة مع آخر لقطة للدليل عبر `GET /api/settings?catalog=stored` دون انتظار الاتصال بالموقع. تحديث الدليل يتم في الخلفية عبر الإعدادات العادية بعد عرض الشاشة؛ فشل الدليل لا يحجب العملاء. الإصدار الحالي للطلب يمنع نتيجة قديمة من استبدال نتائج حفظ أحدث أو التحديث بعد مغادرة الصفحة.
- طلبات GET المتزامنة في المتصفح لنفس المسار والحساب والرؤوس تشترك في طلب واحد فقط أثناء التنفيذ. لا توجد ذاكرة نتائج دائمة؛ القراءة التالية بعد اكتمال الطلب تجلب من جديد. الكتابة تلغي المشاركة مع القراءات السابقة، وحساب مختلف لا يشارك البيانات، والطلبات ذات AbortSignal مستقل لا تدمج.
- قوائم الموقع ذات عدد صفحات معروف تجلب أول صفحة ثم أربع صفحات كحد أقصى بالتوازي في كل دفعة، وتجمعها بترتيب المصدر. أي فشل يرفض القائمة كاملة ولا يخزن نتيجة جزئية. المصدر الذي لا يحدد عدد الصفحات يبقى متتابعًا وفق hasNextPage، والمصفوفات القديمة مدعومة.
- إضافة فهرس مركب لقائمة العملاء حسب الشركة وتاريخ التحديث والإنشاء، مطابق لترتيب `/api/leads`. لا يتغير تصميم تخزين قاعدة CRM العامة أو طابور الكتابة في هذه النسخة.

التحقق: 76 اختبار ربط وبناء CRM، واختبار متصفح مع تعليق استجابة الموقع عمدًا أكد ظهور العملاء قبل اكتمال الدليل، ومشاركة GET دون مشاركة الكائن القابل للتعديل أو بيانات حساب مختلف، وإظهار الأخطاء وإعادة محاولة قراءة جديدة. اختبار القوائم أكد حد التزامن وترتيب الصفحات ورفض النتيجة الجزئية. لم يشغّل خادم CRM المحلي على قاعدة الإنتاج، ولم تُقَس استجابة Render الفعلية. التغيير في CRM فقط؛ علامة صحته `websiteIntegration: 14`، وخادم الموقع يبقى الإصدار 13. يلزم نشر خادم وواجهة CRM؛ لا يوجد وعد بزمن تحميل ثابت، لأن اتصال الموقع وقاعدة البيانات وأداء الاستضافة يظلون عوامل مؤثرة.



## الإصدار 13 — إدارة محتوى الموقع

- الإضافة أعلى قوائم محتوى الموقع، وأزرار التعديل والحذف في الصفوف: آراء الطلاب، الاعتمادات، المقالات والمعارض، الفعاليات السابقة، الخدمات، الأسئلة الشائعة، وقاعدة المعرفة. تبقى الإجراءات مشروطة بتفعيل الكتابة وصلاحيات إدارة الموقع وحساب الاتصال، والحذف يحتاج تأكيدًا صريحًا.
- المقالات: النصوص والعناوين والفقرات والألوان والروابط والدولة والنشر وحقول محركات البحث والمشاركة. الأسئلة: الدولة والتمييز والترتيب. قاعدة المعرفة: نوع المورد والملف والفيديو والجمهور والترتيب والنشر، مع قيم افتراضية متوافقة لإنشاء مورد جديد.
- الفعاليات السابقة: إضافة وتعديل وإزالة عناصر الصور والفيديو. «من نحن»: تحرير النصوص والصور والنشر، وإضافة وتعديل وإزالة المؤسسين ومراحل التاريخ والإحصاءات من حقول منظمة دون كتابة JSON.
- «من نحن» و«الفعالية القادمة» محتوى منفرد لكل صفحة: الإضافة عند عدم وجود سجل عبر مسار الحفظ الحالي PUT، والتعديل والحذف عند وجوده. لا يعرض CRM سجلًا وهميًا عند غياب المحتوى؛ حذف السجل يستخدم معرّفه الأصلي، ولا يحذف بيانات صفحة أخرى.
- أضيفت نقاط حذف محتوى «من نحن» والفعالية القادمة على خادم الموقع مع صلاحيات القسم الحالية وإبطال ذاكرة المحتوى العامة. الفعالية ذات تسجيلات يمنع حذفها؛ يمكن إلغاء نشرها دون حذف تسجيلات الطلاب. قيود حذف الخدمات ذات الطلبات باقية.

التحقق: 74 اختبار ربط، وبناء CRM، وCRUD فعلي للمحتوى على Mongo مؤقتة مع حماية تسجيلات الفعالية، واختبار متصفح لجميع التبويبات التسعة (27 إجراء) باستخدام API وهمية، وحفظ المؤسسين والوسائط والقيم الافتراضية وفحص عرض الموبايل. لم تُعدل بيانات الإنتاج. انشر خادم الموقع وخادم وواجهة CRM؛ علامات الصحة `crmControlVersion: 13` و`websiteIntegration: 13`. النشر الفعلي لم يُختبر.



## الإصدار 12 — الرد وإسناد تذاكر الدعم

- أزرار «رد» و«إسناد» مباشرة في صف التذكرة، ونفس الإجراءات داخل التفاصيل. تعرض الحالة العربية واسم الموظف المسؤول وسجل الردود، وتحمّل تفاصيل التذكرة الحالية قبل تنفيذ الإجراء.
- نموذج الرد يبدأ برسالة فارغة وحالة «تم الرد»، ولا يسمح بإرسال رد فارغ أو إعادة إرسال سؤال الطالب تلقائيًا. يمكن اختيار حالة التذكرة بعد الرد.
- الإسناد من قائمة حسابات الموقع النشطة المخولة بالدعم، مع إمكانية إزالة الإسناد. لا تستخدم القائمة معرفات CRM غير المرتبطة بالموقع. الإجراءات مشروطة بتفعيل الكتابة وصلاحية الدعم وحساب الاتصال.
- نقطة تفاصيل التذكرة على الموقع محمية بنفس صلاحية قائمة الدعم. حفظ الرد يستخدم إضافة ذرية للمصفوفة حتى لا يحذف الرد المتزامن لموظف آخر. الإسناد غير الصالح وحالة الرد غير الصالحة يرجعان خطأ 400، دون تعديل التذكرة.

التحقق: 73 اختبار ربط، وبناء واجهة CRM، واختبار API على Mongo مؤقتة يشمل تفاصيل التذكرة والرد والإسناد وإزالته والصلاحيات والردود المتزامنة، واختبار متصفح مع API وهمية للأزرار والنموذج وسجل الردود وعرض الموبايل وإخفاء إجراءات الكتابة عند تعطيلها. لم تتغير بيانات الإنتاج. انشر خادم الموقع وخادم وواجهة CRM؛ علامات الصحة `crmControlVersion: 12` و`websiteIntegration: 12`. النشر الفعلي لم يُختبر.



## الإصدار 11 — التحكم في الخدمات وطلباتها

- «الخدمات والسكن» يجمع طلبات الخدمات وإدارة تعريفات الخدمات، إلى جانب حجوزات وخيارات السكن والوصول. تبويب إدارة الخدمات متاح أيضًا في المحتوى وفق صلاحيات القسم، ولا تتغير صلاحيات الموظفين تلقائيًا.
- صف الطلب يحمل «إدارة الطلب». داخل التفاصيل زر لتحديث الحالة والإسناد بقائمة موظفي الموقع النشطين المخولين بالخدمات أو الدعم، ويمكن إزالة الإسناد. الملاحظات الداخلية وسجل الحالة والسائق والمستندات تظهر داخل الطلب. فتح المستند يمر بنقطة الوصول الخاصة بالخدمة، وليس نقطة مستندات القبول.
- إنشاء وتعديل وحذف تعريف الخدمة، مع السعر ومدة الخدمة ووصفهما، النصوص والمتطلبات والمستندات والصور والدولة والترتيب والتمييز وربط مرحلة ما بعد القبول. اختيار الدولة يجلب قائمة محدودة الصلاحيات، دون اشتراط صلاحية الدليل الجامعي.
- خادم الموقع كان يتجاهل السعر العددي والمدة ومرحلة الرحلة في حفظ الخدمة؛ أصبحت تحفظ وتتحقق، وتحافظ عمليات تعديل النص فقط على القيم الموجودة. الحذف يمنع تعريفًا له طلبات، ولا يحذف الطلبات نفسها. إلغاء الطلب متاح كتغيير حالة.
- الحفظ يخضع لـ `STUDY_BIRDS_ALLOW_WRITES=true`، وصلاحية `manageServices` أو `manageWebsite`، وصلاحيات حساب الاتصال. الإسناد يستخدم حسابات الموقع، وليس معرّفات موظفين محليين غير مرتبطين. تغييرات الطلب تستخدم الإصدار لمنع الكتابة فوق تحديث موظف آخر.

التحقق: 72 اختبار ربط، وبناء الواجهة، واختبار Express/Mongoose على Mongo مؤقتة للحفظ العددي والإسناد وإزالة الإسناد والتعارض وصلاحيات الموظفين وحذف الخدمة المرتبطة. اختبار متصفح ببيانات API وهمية لتحديث الطلب والسائق وإنشاء الخدمة، وفحص عرض الموبايل. لم تتغير بيانات الإنتاج. انشر خادم الموقع وخادم وواجهة CRM؛ علامات الصحة `crmControlVersion: 11` و`websiteIntegration: 11`. لم يُختبر النشر الفعلي أو إعدادات حساب الاتصال في الإنتاج.



## الإصدار 10 — فلاتر الدليل والمنيو وإجراءات الإدارة

- المدن ولغات الدراسة قوائم اختيار متعددة بارتفاع وعرض باقي حقول الفلتر، مع بحث وإلغاء التحديد. لا تظهر الخيارات كأزرار طويلة خارج الحقول. اختيار الدولة يظل يمسح المدن السابقة، وإغلاق القائمة متاح بالنقر خارجها أو Escape.
- رابط «إدارة الجامعات» `/university-management` يستخدم صلاحية قسم الجامعات، ورابط «إدارة الدول» `/countries` يستخدم صلاحية إدارة الدليل الدراسي. «دليل الجامعات» وأدوات المقارنة وعروض الأسعار تبقى كما هي، ولا تتغير صلاحيات الموظفين تلقائيًا.
- في قوائم الدول والجامعات والبرامج والمنح ومجالات الدراسة، الإضافة أعلى القائمة، والتعديل والحذف في كل صف. تظل هذه الإجراءات مشروطة بتفعيل الكتابة وصلاحيات الإجراء وحساب الاتصال.
- إصلاح إنشاء الدولة: اسم الدولة نص مطابق لنموذج الموقع. نموذج CRM كان يهيئه سابقًا ككائن ترجمة رغم أن الموقع يقبل نصًا، ما كان يمنع الإنشاء الحقيقي.
- لا يمكن حذف دولة تحتوي جامعات أو مجال مرتبط ببرنامج/منشور. القيود السابقة لحذف جامعة ذات برامج/طلبات وبرنامج ذي طلبات مستمرة. تُفصل الروابط أولًا؛ لا يحدث حذف متسلسل للطلبات أو البيانات.

التحقق: بناء الواجهة، واختبارات الربط، وCRUD فعلي للدول والجامعات والبرامج والمجالات على Mongo مؤقتة، واختبار متصفح لجميع عناصر الدليل الخمسة (15 إجراء ببيانات وهمية)، وقوائم الفلتر والمنيو والموبايل. علامات النشر `crmControlVersion: 10` و`websiteIntegration: 10`. لم تُعدل بيانات الإنتاج.


## الإصدار 9 — استكمال إجراءات الشركاء والمجتمع والصفحات

انشر خادم الموقع أولًا ثم خادم وواجهة CRM. التحقق: `crmControlVersion: 9` في صحة الموقع و`websiteIntegration: 9` في صحة CRM. تظل الكتابة مشروطة بتفعيل `STUDY_BIRDS_ALLOW_WRITES=true` وصلاحية القسم والإجراء في CRM وصلاحيات حساب الاتصال في الموقع.

- قسم الشركاء: إنشاء حساب وكيل بكلمة مرور وبيانات الشركة داخل الموقع مباشرة. هوية CRM مستقلة لكل شركة وحساب؛ إعادة الإنشاء بنفس الهوية تعيد الحساب ولا تغيّر بياناته. البريد الموجود يمنع الإنشاء ولا يُكتب فوق حسابه. كلمة المرور لا تحفظ في قاعدة CRM أو سجل العمليات.
- مواد التسويق: رفع ملف حتى 5 ميجابايت مع العنوان والوصف والنوع وحالة النشر، وتعديل المادة وحذفها بطلب صريح. الملفات تمر عبر خادم CRM وتخزين الموقع الحالي؛ مفاتيح التخزين لا تصل للمتصفح.
- المجتمع داخل قسم البريد والدعم: إدارة تعليقات المنشور، وقائمة إيقاف النشر وإنشائه ورفعه، والكلمات المحظورة، وعروض وفرص الطلاب. إيقاف النشر لا يحذف حساب الطالب. إدارة التعليق تتحقق من ارتباطه بالمنشور قبل إرسال التغيير. نوع العرض/الفرصة ثابت عند التعديل.
- المالية: إنشاء وتعديل قواعد مكافآت الطلاب وتعطيلها. نوع حدث المكافأة ثابت في الموقع، ولا تنشئ هذه الإجراءات دفعات أو إيصالات مالية في CRM.
- الطلاب: صفحات من 50 طالبًا وبحث على الخادم في الاسم والبريد والهاتف والجنسية؛ إزالة الاقتصار على أول 200 طالب. المؤشرات المالية والطلبات موضحة للصفحة المعروضة. فتح طالب من رابط مباشر يجلب ملفه حتى إن كان خارج الصفحة الحالية.
- قوائم حجوزات السكن والتأشيرة والمنشورات والبلاغات وسجل الإشراف وحركات المحفظة وعروض وفرص الطلاب: جلب كل الصفحات بدل الحدود السابقة 200/300/500. الطلب الاختياري `crmPagination=1` يبقي استجابات الموقع القديمة دون هذا الخيار بنفس صيغة المصفوفة. ترتيب الصفحات يتضمن المعرّف لمنع تداخل سجلات ذات تاريخ متساوٍ. أهلية التأشيرة تُفلتر قبل تقسيم الصفحات.

التحقق: 71 اختبارًا للربط، اختبارات Express/Mongoose مع قاعدة Mongo مؤقتة تشمل 501 حجز و301 منشور وحركة محفظة، واختبار متصفح باستخدام API وهمية يشمل 211 طالبًا والرفع والحذف وإنشاء الوكيل والمكافآت والتعليقات والإيقاف والبحث والموبايل؛ وبناء واجهة CRM. لم تُكتب أو تُحذف بيانات الإنتاج أثناء الاختبار. رفع Git لا يثبت نجاح النشر الفعلي أو إعدادات حساب الاتصال.

المتبقي: موصل بريد الصندوق الفعلي يحتاج تحديد الخدمة والعنوان. تخزين CRM العام وطابور الكتابة المشترك لم يتغيرا، وبعض الخدمات ما زالت تستخدم محررات مشتركة داخل الأقسام. ملاحظات الطلاب والمهام والأقساط تظل متابعة داخل CRM، لا تُنشر تلقائيًا في لوحة الطالب العامة. حسابات الموظفين القائمة تحتاج ربط الهوية ومراجعة الصلاحيات؛ لا يتم منح صلاحيات جماعية. التطبيق مؤجل. اختبارات الكتابة حسب أدوار الموظفين على النشر الفعلي لم تتم.


## الإصدار 8 — إصلاح الدليل والدعم وتحسين التحميل

انشر خادم الموقع أولًا ثم خادم وواجهة CRM. علامات التحقق: `crmControlVersion: 8` في الموقع و`websiteIntegration: 8` في CRM. التطبيق ما زال مؤجلًا.

- عرض جميع الجامعات، حتى التي ليس لها برامج، مع البحث والتحرير والإنشاء داخل القسم. إنشاء الدول متاح بجانب الجامعات وفي إدارة الدليل. تبقى المقارنة وعروض الأسعار موجودة.
- فشل قراءة المنح لا يمنع قراءة باقي الدليل. استبدال الدليل القديم لا يحدث بعد قراءة جزئية. تحفظ آخر قوائم الموقع الناجحة لكل شركة، مع تنبيه عند عرضها بسبب الانقطاع. رفض الصلاحية لا يتحول إلى قائمة مخزنة صامتة.
- دعم الطلاب يعرض سجل الردود وقائمة موظفي الموقع النشطين المخولين بالدعم. المصدر يرفض إسناد التذكرة لموظف غير مخول. المستشارون الجدد المنشؤون من CRM يحصلون على صلاحية الدعم؛ صلاحيات الحسابات القائمة لا تتغير تلقائيًا، ويمكن للمسؤول تعديلها من محرر الحساب.
- إسناد وحالة وأولوية ووسوم محادثات الموقع متاحة داخل CRM، وتحفظ كمتابعة داخلية لكل شركة وهوية مصدر. الرسائل نفسها تستمر عبر API الموقع حسب جهات الاتصال المسموحة لحساب الاتصال؛ هذا لا يمنح الاطلاع على جميع المحادثات.
- محررات الجامعات تدعم المستندات المطلوبة والاعتمادات وفقرات الصفحة. البرامج تدعم المجالات الإضافية والشروط وفرص العمل وقوائم اللغة والدرجة ومجال الدراسة مع الحفاظ على القيم القديمة. نموذج إنشاء الطالب يشمل بيانات ملفه الإضافية.
- تحميل الصفحات أصبح عند فتحها، بدل تحميل كل صفحات CRM مقدمًا. التبويبات غير المفتوحة لا تحمل قوائمها مسبقًا. القوائم المتزامنة تشترك في قراءة واحدة بتخزين مؤقت قصير يلغى عند الكتابة. إعادة قراءة بيانات لم تتغير لا تعيد كتابة ملفات الربط. حجم JavaScript الأساسي انخفض من نحو 675 إلى 339 كيلوبايت قبل الضغط.

التحقق محلي ومعزول: اختبارات الربط، خادم موقع مع Mongo مؤقتة، وبناء الواجهة. المتصفح استخدم API وهمية لاختبار الإنشاء والرد والإسناد وعرض الجامعة بلا برامج وعدم كسر المالية والقبول. لم تحدث عمليات حذف أو تعديل بيانات إنتاج أثناء هذه الاختبارات.

الحدود: تخزين CRM العام وطابور الكتابة المشترك لم يتغيرا. قوائم المصدر ذات الحدود الثابتة ما زالت تعرض تنبيهًا؛ جلب كل التاريخ يحتاج استكمال صفحات المصدر. ملاحظات الطالب والمهام وجدول الأقساط تظل ميزات متابعة CRM، ولا تتحول تلقائيًا إلى بيانات صفحة الطالب العامة في الموقع. البريد يحتاج موصل الصندوق كما في الأقسام التالية. هذا الإصدار لا يعني اكتمال جميع ميزات الربط.


## الإصدار 7 — استكمال التحكم والمطابقة

هذا الإصدار يحل محل القيود المذكورة في الإصدارات السابقة أدناه. يجب نشر خادم الموقع أولًا، ثم خادم وواجهة CRM. بعد النشر يعرض خادم CRM `/api/health` القيمة `websiteIntegration: 7`، وخادم الموقع `crmControlVersion: 7` مع معرّف البناء عند توفيره من منصة النشر. التطبيق مؤجل بناءً على طلبك.

- **القبول:** جميع حالات الموقع لها حالات مميزة داخل CRM. تعديل الملاحظات لا يرسل تغييرًا للحالة. الحفظ يستخدم نسخة الطلب ويرفض التعديلات المتعارضة. المسؤول في النموذج الأصلي ينعكس على مستشار الموقع عبر هوية موظف صريحة؛ الموظف غير المرتبط لا يُسند بالاسم أو البريد. يجب أن يكون حسابه نشطًا ومخوّلًا في الموقع. رفع مستند أو إزالته يحدّث نسخة الطلب المحلية. الحذف الصريح متاح للمخولين، ويحفظ ملف CRM في أرشيف `websiteDeletedRecords`؛ الطلب ذو تاريخ مالي لا يُحذف.
- **الطلاب:** تحرير بيانات التعليم والإقامة واللغات والدول المستهدفة وولي الأمر والطوارئ واختبار الإنجليزية، إضافة إلى بيانات الحساب السابقة. كلمات المرور الفارغة لا تغيّر كلمة مرور الطالب.
- **الدليل والمحتوى:** تحرير صور الجامعة وأعداد الطلاب والترتيب ونطاق الرسوم، ومستندات البرامج المطلوبة. رفع صور الجامعة والمحتوى من الجهاز. حذف المحتوى متاح فقط للأنواع التي يوفر المصدر حذفها، وبطلب صريح من الموظف.
- **الاستشارات:** إنشاء مواعيد المستشارين وإيقاف المواعيد المتاحة وتفعيلها وإلغاء الحجز، بجانب تسجيل النتيجة. تبقى قيود الوقت والحجز وصلاحيات المستشار على خادم الموقع.
- **الخدمات والسكن:** إنشاء وتحرير وتعطيل خيارات السكن. لا يمكن حذف خيار له حجوزات أو تخفيض سعته عن عدد الحجوزات المؤكدة. رفع مستندات الخدمات يستخدم تخزينًا خاصًا وروابط مؤقتة، وتبقى قيود العدد والحجم محفوظة. يمكن تعديل حساب الوكيل وبيانات الشركة والمقر والرقم الضريبي والهاتف، دون تجاوز إجراءات التوثيق أو السحب.
- **الدعم:** تصعيد التذكرة وإلغاء التصعيد وتحديد الطوارئ وفتح المرفق الخاص؛ إشعارات هذه الإجراءات تُرسل عبر المصدر.
- **المالية:** «مطابقة دفعات الموقع» من سجل الفاتورة تعرض المحصل والمحفظة ورصيد CRM وإثباتات الدفع. استيراد الإثباتات المعتمدة ينشئ سندات محلية ثابتة بمعرّف الإثبات، مرة واحدة، ولا يغيّر رصيد الموقع أو يجمعه مرة أخرى. الإثبات المتغير أو الفرق المتعارض يمنع الاستيراد؛ الفرق بلا إثبات يبقى ظاهرًا للمراجعة. السند المستورد لا يُحذف أو يُعدّل محليًا. الحفظ والحذف الماليان يحميان الفواتير ذات الدفعات والإثباتات والمحفظة وعمليات الدفع الجارية. تعديل المحفظة إجراء مستقل ومصرح به مع سبب إلزامي، ولا يحوّل رصيدها إلى إيراد أو سند قبض.

الصلاحيات: يلزم فتح القسم بالإضافة إلى إجراء مناسب. توجد إجراءات `manageConsultations` و`manageServices` و`manageSupport` و`deleteApplication` ضمن إعدادات الصلاحيات المخصصة. تستخدم المالية `createInvoice` و`recordPayment` و`deleteInvoice`، والوثائق `reviewDocument`، وملفات الطلاب `createApplication`. تبقى إدارة حسابات الموظفين وأدوارهم وصلاحياتهم تحت `manageUsers`. صلاحية `manageWebsite` الإدارية لا تمنح فتح قسم غير مسموح. كتابة الموقع تتطلب `STUDY_BIRDS_ALLOW_WRITES=true` أيضًا؛ حساب الاتصال في الموقع قد يرفض إجراء لا يملكه حتى إذا سمح به CRM.

التحقق المحلي: 61 اختبار ربط CRM، واختبار API الموقع على Mongo مؤقتة يغطي حفظ الحالات، تعارض الطلبات، الإسناد، ملفات الخدمات، الملف الدراسي والدفعات. نجح بناء CRM. اختبارات المتصفح ببيانات وهمية تغطي النماذج والصور والسكن والاستشارات والدعم والمطابقة والأقساط والمهام، وعرض 390 و768 بكسل. لم يُشغّل خادم CRM المتصل بقاعدة حقيقية، ولم تُحذف بيانات إنتاج. نجاح الاختبارات لا يثبت صلاحية الرمز أو نجاح نشر Render.

الحدود المتبقية خارج التحكم المنفذ: تشغيل البريد يحتاج موصل الصندوق، ومحادثات الموقع تبقى مقيدة بالحساب المتصل. السندات المدفوعة خارج CRM بلا إثبات معتمد لا تُختلق تلقائيًا، وتحتاج مراجعة الفرق. قوائم المصدر التي تضع حدًا لعدد النتائج قد لا تعرض التاريخ كله؛ الاستجابة الناقصة لا تحذف ملفات CRM. يلزم التحقق من النسخ المنشورة والاتصال الفعلي بعد النشر.

## الإصدار 6 — ميزات CRM لسجلات الموقع

هذه الإضافة توسع الإصدار 5 أدناه. تحتاج نشر خادم الموقع أولًا، ثم خادم وواجهة CRM. التطبيق ما زال مؤجلًا. يعرض `/api/health` في CRM القيمة `websiteIntegration: 6` بعد نشر الخادم.

- فتح الطلاب أو القبول أو المالية أو الموارد البشرية يحفظ علاقة ثابتة بمعرّف الموقع داخل القسم الأصلي. التحديثات الخلفية تفعل ذلك أيضًا. تُرقّى السجلات المرتبطة السابقة بنفس معرّف CRM، دون دمج أشخاص بالاسم أو البريد ودون حذف سجل غائب من استجابة محدودة.
- ملف الطالب يجمع طلباته وفواتيره عند فتحه حسب صلاحيات الموظف. يمكن حفظ ملاحظات المتابعة والمستشار وإنشاء مهام في جدول المهام الأصلي. الملاحظات والمهام لا تستبدل ملف الموقع أو كلمة مرور الطالب.
- طلبات الموقع تدعم نموذج القبول الأصلي ومراحل المتابعة ورفع المستندات ومراجعتها. يبقى برنامج الموقع محددًا بمعرّفه حتى مع تشابه الأسماء واختلاف اللغة. آخر نسخة من المستند هي الحالية، ويبقى تاريخ النسخ المنفصلة محفوظًا؛ فتح الملف يستخدم البوابة المحمية. المسؤول المحلي ومراحل CRM مستقلة عن تعيين مستشار الموقع، الذي يُدار من إجراء الإسناد الموجود في إدارة السجل.
- يمكن تسجيل سند على فاتورة أنشأها الموقع، وإضافة ملاحظات وخطة أقساط من المالية الأصلية. مجموع الأقساط يجب أن يساوي مبلغ الفاتورة، ولا يمكن حذف قسط له سند أو تخفيضه عن المدفوع. الرصيد المشترك يأتي من الموقع ولا تُجمع معه السندات المنعكسة عليه مرة ثانية. تحديث الدفعة يستخدم رقم النسخة؛ تغيير الرصيد أو عملة السند يرفض العملية حتى التحديث. تُمنع التغييرات عند وجود إثبات دفع أو محفظة أو دفعة خارجية تحتاج تسوية، وتظل فواتير ربط آخر محمية.
- موظفو الموقع يحصلون على ملف موارد بشرية يدعم الحضور والإجازات والراتب والأهداف والمستندات. الاستيراد لا ينشئ تسجيل دخول CRM ولا يمنح صلاحيات أو راتبًا تلقائيًا. ربط مستخدم موجود يعتمد على معرّف حساب الموقع الصريح؛ تشابه البريد وحده لا يغيّر حسابًا مستقلاً عند الإقالة أو الحذف.
- حقول الموقع المشتركة تُكتب إليه عند الحفظ المصرح به، أما ملاحظات الطلاب والمهام وخطط الأقساط والرواتب ومراحل المتابعة فتبقى بيانات CRM مرتبطة بنفس السجل. تظهر السجلات المرتبطة في البحث والتقارير والعدادات الأصلية. الصلاحيات و`STUDY_BIRDS_ALLOW_WRITES` ما زالت مطلوبة لكتابة الموقع؛ المتابعة المحلية لا تحتاج تفعيل كتابة الموقع.

التحقق: بناء CRM ناجح، و54 اختبار ربط CRM ناجح، واختبار الموقع على Mongo معزولة يغطي الفواتير الأصلية والدفعات الجزئية وتعارض النسخة ودفعات القنوات الأخرى. نجح اختبار واجهات الملفات والقبول والأقساط والموارد البشرية ببيانات وهمية، وفحص العرض عند 390 و768 بكسل بدون تجاوز عرض الشاشة. لم يُشغّل خادم CRM المحلي المتصل بقاعدة حقيقية، ولم تُحذف بيانات إنتاج. هذه النتائج لا تثبت نجاح الاتصال أو نشر الإصدار على Render.
## الإصدار 5 — الكتابة من الأقسام الأصلية

هذا الإصدار يحتاج نشر خادم الموقع وخادم CRM معًا. التطبيق مؤجل حاليًا. تفاصيل الإصدارات السابقة أدناه توثّق الوضع السابق؛ التغييرات التالية تحل محل حدود الإنشاء المذكورة فيها.

التحقق المحلي للإصدار 5: نجح بناء الواجهتين، و44 اختبار ربط CRM و26 اختبارًا للموقع تتضمن حسابات فعلية وملفات وفواتير على Mongo مؤقتة. نجح فحص الأقسام الموحدة على الكمبيوتر والموبايل، وإنشاء حساب طالب من نموذج CRM، ودخول المساحة المضمنة دون رمز في الرابط أو أخطاء JavaScript. الفحص الشامل للموقع: 82 نجاحًا من 90؛ الاختبارات الثمانية الفاشلة تفشل أيضًا على نسخة Git السابقة بعد إصلاح أخطاء تحميلها فقط. لم تُنفذ هذه الفحوص على بيانات الإنتاج، ولا تثبت تفعيل Render.

- الموقع هو دليل الجامعات والبرامج والمنح المعتمد. عند تشغيل CRM مع الربط المفعّل، تُقرأ قائمة الموقع بنجاح أولًا، ثم تحفظ نسخة الدليل القديم في `websiteCatalogArchive` بكتابة مستقلة، وبعد حفظها تستبدل القوائم الثلاث النشطة فقط. يحتفظ `websiteCatalogCutover` بمرجع النسخة. لا تتغير سجلات الطلاب والطلبات والفواتير القديمة ولا الدول المستقلة. إذا فشل الاتصال، يحتفظ CRM بالدليل القديم ويكمل التشغيل. تعطيل الربط لا يعيد الدليل القديم تلقائيًا؛ الاستعادة تتم من النسخة المحفوظة.
- أزرار إضافة جامعة أو برنامج أو منحة تحفظ في الموقع نفسه. تعديل وحذف الدليل يعملان على المصدر؛ حذف جامعة أو برنامج له طلبات، أو منحة لها تقديمات، يُرفض لحماية التاريخ.
- قسم الطلاب ينشئ حساب موقع حقيقيًا بكلمة مرور مع ملف الطالب. إعادة المحاولة تستخدم هوية ثابتة ولا تغيّر كلمة المرور أو ملف حساب موجود. يمكن إنشاء حساب لطالب CRM قديم مع إبقاء معرّفه وتاريخه، أو ربط حساب موقع موجود صراحةً بمعرّفه وبنفس البريد. تعارض البريد يُرفض دون استبدال الحساب.
- الموظفون والمستشارون الجدد يحصلون على حساب موقع مرتبط، ودور وصلاحيات مناسبة. مسؤول CRM لا يصبح مسؤول موقع تلقائيًا. تعديل الاسم والبريد وكلمة المرور والتفعيل ينعكس على الحساب المرتبط. يمكن ربط مستخدم CRM قديم من شاشة تعديل المستخدم بمعرّف حساب الموقع. حساب الاتصال نفسه لا يمكن تعطيله أثناء تنفيذ الربط.
- إنشاء طلب قبول لطالب مرتبط يسجل طلبًا في الموقع؛ اختيار البرنامج يحدد الجامعة والدرجة واللغة. تغيير الحالة والملاحظات وموعد الالتحاق ومعلومات القبول يحدّث المصدر. كلمات مرور بوابات الجامعات تبقى في CRM ولا تُنسخ إلى الموقع.
- رفع مستند لطلب مرتبط يخزنه في تخزين الموقع الخاص، والمراجعة تستخدم رقم النسخة لمنع استبدال قرار موظف آخر. إزالة المستند من الطلب تفصله عن الطلب وتحفظ الملف وتاريخ مراجعته للطالب. فتح الملف يستعمل رابط الوصول المحمي.
- إنشاء فاتورة من قسم المالية لطالب مرتبط ينشئ فاتورة بالموقع. الدفعات الجزئية والإلغاءات تحدّث رصيد الفاتورة وتحتفظ بتاريخ التغييرات. الدفع والمحفظة بالموقع يحسبان المتبقي بعد دفعات CRM. تتوقف كتابة رصيد CRM إذا كان هناك إثبات دفع أو جلسة دفع فعالة بالموقع حتى تتم التسوية. لا تنشأ حركات محفظة أو إثباتات دفع مكررة. الفواتير التي لها تاريخ دفع لا تحذف تلقائيًا.
- المهام والمكالمات والمتابعات والمبيعات والحضور والرواتب وباقي ميزات CRM تبقى على بيانات CRM الأصلية، وتتاح داخل لوحة الموقع عبر مساحة CRM المشتركة للحسابات المرتبطة. هذا وصول لنفس الخدمة والبيانات، دون إنشاء نسخ مستقلة لهذه الأقسام في قاعدة الموقع.

### إعداد النشر

على خادم CRM: اضبط `STUDY_BIRDS_ENABLED=true` و`STUDY_BIRDS_ALLOW_WRITES=true` مع رابط API الموقع ورمز حساب إدارة مخوّل. `STUDY_BIRDS_COMPANY_ID` هو معرّف شركة CRM القائمة. انشر تحديث الموقع أولًا، ثم CRM. `websiteIntegration: 5` في صحة CRM يميز هذا الإصدار. احتفظ بنسخة احتياطية كاملة قبل أول تفعيل، ثم تحقق من أرشيف الدليل ومن السجلات التاريخية.

لمساحة CRM داخل الموقع: اضبط على خادم الموقع `CRM_API_URL` (خادم CRM مع `/api`) و`CRM_WEB_URL` (أصل واجهة CRM دون مسار) و`CRM_COMPANY_ID`. أنشئ سرًا عشوائيًا مستقلًا لا يقل عن 32 حرفًا وضع القيمة نفسها في `STUDY_BIRDS_SSO_SECRET` على الخادمين. مثال توليد محلي: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. لا تحفظ القيمة في Git ولا في متغيرات واجهة المستخدم. في واجهة CRM اضبط `VITE_STUDY_BIRDS_WEB_ORIGIN` إلى أصل الموقع الفعلي ثم أعد البناء.

دخول المساحة يتطلب ربط حساب الموظف أو المسؤول فعليًا بمعرّف مستخدم CRM. التوقيع مدته دقيقة، والرمز لا يمر في عنوان الرابط، وتؤخذ صلاحيات الجلسة من حساب CRM. منع إعادة استخدام التوقيع محلي لكل عملية؛ استخدم عامل CRM واحدًا كما تتطلب آلية تخزين CRM والمتابعة الحالية.

الاختبارات المحلية المعزولة لا تؤكد إعدادات Render الفعلية أو صلاحية رمز الموقع. بعد النشر اختبر بحسابات اختبار إنشاء طالب وتعديله، طلب قبول وملف، فاتورة ودفعة جزئية، ودخول مساحة CRM. البريد يحتاج موصل صندوق البريد كما هو موضح أدناه.

## ما تم تنفيذه

- قسم «طلبات الموقع»: بحث، تفاصيل، قراءة الطلبات وإجراءات تحديثها عبر API الموقع.
- دليل الدول والجامعات والبرامج والمنح من الموقع للاختيارات الجديدة؛ دليل CRM القديم محفوظ في أرشيف مستقل، وتستبدل قوائم الجامعات والبرامج والمنح النشطة بعد نجاح الاتصال وحفظ الأرشيف.
- واجهات التأمين والمعادلة والتأشيرة ومتطلبات التأشيرة وتعيين المستشار ومراحل ما بعد القبول وبيانات السائق.
- إنشاء وتحرير الدول والجامعات والبرامج والخدمات والأسئلة الشائعة وقاعدة المعرفة. تحفظ عملية التعديل حقول السجل غير المعروضة في المحرر.
- متابعة دورية اختيارية للطلبات، وإشعارات للطلبات الجديدة، وتوزيع بالتناوب على موظفين تحددهم الإدارة.
- الربط بمعرّفات المصدر بأقسام الطلاب والقبول والمالية، وتحويل تسجيلات الفعاليات إلى العملاء المحتملين. لا يجري دمج بالاسم أو الهاتف.
- الفواتير المرتبطة لا تنشئ دفعات أو حركات محفظة إضافية. تُراجع الطلبات والفواتير وتُحدّث سجلاتها الأصلية من أقسام القبول والمالية نفسها.
- استقبال بريد «تواصل معنا» من موصل صندوق البريد، ومحادثات حساب الموقع المتصل حسب جهات الاتصال التي يسمح بها الموقع.
- صلاحية `website` لعرض القسم، وصلاحية `manageWebsite` منفصلة للكتابة، وسجل إجراءات الكتابة مع موظف CRM ونتيجة الطلب.

## إعداد الاتصال

على خادم CRM فقط:

```dotenv
STUDY_BIRDS_API_URL=https://study-birds1.onrender.com/api
STUDY_BIRDS_API_TOKEN=TOKEN_FOR_AUTHORIZED_WEBSITE_ACCOUNT
STUDY_BIRDS_ENABLED=true
STUDY_BIRDS_ALLOW_WRITES=false
```

الرابط المكتشف من إعدادات الموقع وفحص `/api/health` نجح. لا تحفظ الرمز في Git أو متغيرات واجهة Vercel. رمز الموقع قد ينتهي؛ حدّثه على خادم CRM عند انتهاء الصلاحية. هذه النسخة لا تحفظ كلمة مرور الموقع ولا تنتحل هويات موظفيه.

1. اضبط رمز حساب الموقع الذي يملك الصلاحيات المطلوبة، ثم افتح «طلبات الموقع» واضغط اختبار الاتصال.
2. اضغط فحص صلاحيات الأقسام. ظهور خطأ 403 يعني نقص صلاحية حساب الموقع، وليس قائمة خالية.
3. على بيئة اختبار، فعّل `STUDY_BIRDS_ALLOW_WRITES=true` واختبر الإجراءات المطلوبة على سجلات اختبار. الحفظ يشغّل إشعارات الموقع وآثاره المعتادة.
4. اربط موظفي CRM بمعرّفاتهم على الموقع من إعدادات التوزيع، واختر مستلمي الإشعارات. عند تفعيل التوزيع يُسند الطلب الجديد إلى موظف CRM المطابق لمستشار الموقع قبل التوزيع بالتناوب. اختيار مستشار الموقع يتم من قائمته الفعلية في ملف الطلب.

## إشعارات الطلبات والتوزيع

من قسم الموقع، اختر أنواع الطلبات والموظفين ثم اضغط «قراءة الطلبات الجديدة». أول قراءة لكل نوع تحفظ خط أساس دون إشعارات جماعية للسجلات القديمة. القراءات اللاحقة تُشعر بالطلبات الجديدة مرة واحدة. نقص عناصر قائمة محدودة لا يحذف تاريخ CRM.

لتشغيل المتابعة الخلفية على عامل Render واحد:

```dotenv
STUDY_BIRDS_SYNC_ENABLED=true
STUDY_BIRDS_COMPANY_ID=EXISTING_CRM_COMPANY_ID
STUDY_BIRDS_SYNC_INTERVAL_MS=120000
```

المزامنة الخلفية للقراءة فقط؛ لا تعدّل الموقع. تعيين صاحب الطلب داخل CRM مستقل عن تعيين مستشار الموقع. لا تشغّل عدة عمال بهذه الإعدادات؛ تخزين CRM الحالي لا يوفر قفلًا موزعًا لهذه المتابعة. على Vercel استخدم عاملًا خارجيًا أو جدولة تطلب `/api/integrations/website/sync` بحساب CRM مخوّل؛ المؤقت الداخلي لا يعمل أثناء توقف دوال Vercel.

## ربط السجلات بالأقسام الحالية

من تفاصيل السجل اختر «ربط بالقسم الحالي في CRM». لا تتكرر النسخة عند إعادة الربط؛ يُستخدم زوج الشركة ومعرّف المصدر. السجلات المستقلة لا تُحذف أو تُستبدل، والطلاب المتشابهون بالاسم لا يُدمجون تلقائيًا.
قراءة الطلبات اللاحقة تحدّث حالة الطلب والفاتورة المرتبطين. لا تُنقل المستندات السرية إلى ملفات عامة؛ تُفتح بروابط مؤقتة من واجهة الموقع.

## بريد «تواصل معنا»

نموذج الموقع يرسل بريدًا ولا يحتفظ بسجل قابل للسحب. يحتاج موصل صندوق البريد إلى إرسال الرسائل الواردة إلى:

```http
POST /api/integrations/website/mail
Authorization: Bearer <STUDY_BIRDS_MAIL_SECRET>
Content-Type: application/json
```

```json
{"messageId":"unique-mail-provider-message-id","name":"Student","email":"student@example.test","phone":"","subject":"Contact request","message":"Message text"}
```

اضبط `STUDY_BIRDS_MAIL_SECRET` و`STUDY_BIRDS_COMPANY_ID` على خادم CRM، ثم أنشئ قاعدة/موصلًا في خدمة البريد يحوّل الرسائل لهذا المسار. يمنع `messageId` تكرار الاستقبال. موصل البريد نفسه يحتاج بيانات صندوق البريد ومزوّده؛ لم يُضبط حساب بريد فعلي أثناء التطوير. لا تُرسل الأسرار في رابط URL.

## محادثات الموقع

في «الصندوق الموحد» تظهر محادثات الحساب المتصل مع محادثات CRM في القائمة نفسها. تظهر أحدث الرسائل التي يسمح بها API للحساب المتصل. الإرسال يحتاج صلاحية الكتابة. هذا ليس صندوقًا إداريًا لكل محادثات المستخدمين؛ توسيع الاطلاع إلى محادثات حسابات أخرى يحتاج دعمًا وصلاحيات من الموقع. رسائل موصل البريد تظهر في القائمة نفسها؛ «رد بالبريد» يفتح برنامج البريد، ولا يدّعي إرسال رسالة من خادم CRM.

## النشر والتحقق

Render ينشر خادم `server`، وVercel ينشر الواجهة من `client/dist`. متغير `VITE_API_URL` في Vercel هو رابط خادم CRM بدون `/api`؛ يختلف عن `STUDY_BIRDS_API_URL` الذي يشير لخادم الموقع وينتهي بـ `/api`.

```bash
node --test server/src/integrations/website/website.test.js server/src/integrations/website/website.workflow.test.js server/src/integrations/website/website.content.test.js server/src/integrations/website/website.sections.test.js server/src/integrations/website/website.unified.test.js
npm run build --prefix client
```

نجح 35 اختبار وحدة وبناء الواجهة وفحص الواجهة بسجلات وهمية. لم تُجر اختبارات حفظ على الموقع الحقيقي ولم تُغيّر بياناته أثناء التطوير.
بعد النشر يعرض `/api/health` القيمة `websiteIntegration: 4` ومعرّف البناء `buildCommit` للتحقق من وصول الإصدار للخادم.

## الحدود الحالية

- بعض واجهات الموقع تضع حدًا لعدد السجلات دون صفحات؛ تُظهر الشاشة هذا الحد، ولا تدّعي اكتمال التاريخ.
- انقطاع الاتصال أثناء الحفظ قد يعني أن الموقع حفظ الطلب بالفعل. حالة `failed-or-unconfirmed` تستلزم تحديث السجل قبل إعادة المحاولة؛ لا تُعاد الكتابة تلقائيًا.
- إنشاء نسخ مرتبطة محليًا وإعدادات التوزيع تغيّر بيانات CRM بإضافة سجلات الربط فقط. لا توجد ترحيلات أو حذف للقوائم القديمة.
- تفعيل الاتصال الحقيقي والبريد والتحقق من النشر يحتاج بيانات الحساب والخدمات. الإعدادات الافتراضية تعطل الاتصال والكتابة والمتابعة الخلفية.

## الدمج داخل أقسام CRM — الإصدار 4

قسم «طلبات الموقع» أصبح «إعدادات ربط الموقع». الطلاب والقبول والفواتير والبرامج والدليل الجامعي والموظفون والمحادثات تعرض بيانات النظامين في القوائم والبطاقات الأصلية نفسها، وبنفس تصميم CRM، دون قوائم منفصلة حسب المصدر. زر «إدارة السجل» داخل الصف أو التفاصيل يفتح الإجراءات المتاحة للسجل الأصلي، ثم يحدّث القائمة بعد الحفظ. تبويبات القسم تخص أنواع البيانات مثل المستندات أو إثباتات الدفع، وليس مصدرها.

التوحيد بالعرض والهوية دون ترحيل البيانات: سجل CRM المرتبط صراحة بمعرّف الموقع يظهر مرة واحدة وتبقى بياناته المخزنة محفوظة. السجلات المستقلة لا تُدمج بالاسم أو الهاتف؛ تطابق الاسم وحده لا يثبت أنها سجل واحد. تحفظ البرامج ذات اللغات المختلفة معرّفاتها المستقلة. تعذّر قراءة الموقع لا يمحو بيانات CRM، وأخطاء الاتصال والصلاحيات ظاهرة.

| قسم CRM | بيانات الموقع وإجراءاتها |
| --- | --- |
| الطلاب | الطلاب وولي الأمر وطلاب الوكلاء؛ التأمين والمعادلة من تفاصيل الطالب |
| القبول والتسجيل | الطلبات والمستندات والتأشيرات؛ الحالة والمستشار وما بعد القبول وطلب مستند ومراجعة الوثائق |
| المالية | الفواتير وإثباتات الدفع والسحوبات وحركات المحفظة؛ تحديث الفاتورة ومراجعة الإثبات والسحب |
| الاستشارات | الحجوزات وتسجيلات الفعاليات واختبار التوجيه واهتمامات الطلاب |
| الاستقبال | استقبال المطار والفعاليات |
| الصندوق الموحد | تذاكر الدعم وبلاغات المجتمع والمنشورات وسجل الإشراف؛ بريد الموصل ومحادثات الحساب المتصل |
| الجامعات والبرامج | بيانات الموقع وتحريرها؛ حسابات الجامعات داخل قسم الجامعات |
| المنح | طلبات الموقع إلى جانب كتالوج المنح المستقل |

| الإعدادات | إعدادات الموقع وحساباته إلى جانب إعدادات CRM |
| الخدمات والسكن (جديد) | الخدمات والسكن وخياراته واستقبال المطار وبيانات السائق |

الدليل القديم يُقرأ من `/api/education-catalog?source=crm`. اختيارات الطلبات الجديدة ما زالت تعتمد على دليل الموقع عند تفعيل الربط. لا تتغير بيانات HR والمهام والمكالمات والمبيعات والحضور والأقسام المستقلة الأخرى.

الوصول للسجلات وإجراءاتها يتطلب صلاحية قسم CRM المقابل، مع استمرار قيود حساب الموقع نفسه. حفظ بيانات الموقع يحتاج أيضًا صلاحية `manageWebsite` و`STUDY_BIRDS_ALLOW_WRITES=true`. إعطاء صلاحية الكتابة وحدها لا يفتح أقسامًا أخرى. إعداد الإشعارات والتوزيع وسجل الربط يبقى للإدارة في إعدادات الربط. إشعارات الطلبات الجديدة تفتح القسم المقابل مباشرة.

تحقق الإصدار الحالي: 35 اختبار وحدة وبناء الواجهة. فحص المتصفح قوائم الطلاب والقبول والفواتير والبرامج والدليل الجامعي والموظفين والصندوق الموحد ببيانات وهمية من النظامين، وتحديث حالة طلب وإرسال رد عبر مسار الموقع، وقراءة بريد الموصل. فُحص عرض الطلاب بعروض 320 و390 و768 و1440 بكسل دون تجاوز عرض الشاشة، ولم تظهر أخطاء JavaScript. لم يُشغّل خادم قاعدة البيانات أو يُنفذ حفظ على الموقع الحقيقي. الاختبارات لا تثبت صلاحية الرمز أو اتصال النشر الفعلي.

الحضور والإجازات والرواتب المستقلة تبقى خاصة بسجلات موظفي CRM؛ API الموقع لا يوفر عمليات حضور مماثلة. ملخصات المستندات والمدفوعات المحلية لا تُختلق للسجل المرتبط؛ تفاصيل ملفات الموقع تُراجع من «إدارة السجل». قوائم الموقع المحدودة تظل محدودة حسب API ولا تعني اكتمال جميع السجلات التاريخية.

الحدود: البريد يحتاج موصل الصندوق، والمحادثات مقيدة بالحساب المتصل. بعض قوائم API محدودة العدد ويظهر ذلك في القسم. حركات المحفظة والإحصاءات والاهتمامات والبلاغات تُعرض وفق الإجراءات التي يتيحها API؛ هذا التحديث لا يضيف حذفًا أو إنشاء حركات مالية. إنشاء فواتير الموقع وحسابات الجامعات متاح من القسم المقابل. رفع مستند طالب جديد وإنشاء حساب موظف أو طالب لا يوفرهما API الإدارة الحالي بنفس حساب الاتصال، ويحتاجان واجهاتهما الأصلية أو إضافة مسارات للموقع؛ لم يُعدل الموقع لتجاوز ذلك. مراجعة الملفات الموجودة وتحديث الطلبات والفواتير متاحة من CRM.
